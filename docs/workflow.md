# レポートを作るまでの手順

相談を始めてから、案を選んで予約の前の確認をするまでの流れです。段階ごとに、誰が何をして、何を保存するかを書きます。

- なぜそうするかは [design.md](design.md) にあります（段階の深さは §3、データの持ち方は §8、レポートの考え方は §17、試運転でわかったことは §18・§19）。
- 相談役と調査役への細かい指示は、定義のファイルが正です（`plugins/travel-agent/agents/*.md`、`plugins/travel-agent/skills/report/SKILL.md`）。ここには、流れと、人が確かめるところだけを書きます。
- データの場所と消し方は [README](../README.md) の「保存するデータと、消し方」にあります。下の `trips/<旅行ID>/` は、その場所の下です。

## 1. 全体の流れ

| 段階 | 相談役（concierge）がすること | 呼ぶ調査役 | ユーザーが決めること | 保存するもの |
|---|---|---|---|---|
| 1. 聞き取り | 日程、人数、出発地、予算（固さも）、やりたいこと、外せない予定を、短い往復で聞く（1回に1〜3問）。好みは「前の旅行で良かったこと、嫌だったこと」で聞く | なし | 条件 | `conditions.json`、`log.md` |
| 2. 行き先の一覧（ラフ案） | 候補の地域を、所要時間、往復の運賃、注意で、1地域1行の表にする。条件に合わない地域は、理由と数字を付けて外す。宿はまだ調べない | access（1本） | どこでプランを作るか | `access.json` |
| 3. プラン作り | 選ばれた地域ごとに、宿の候補を集めさせ、その候補と access の値を渡して、プランを1案組ませる。「合う宿がない」と返ったら scout を呼び直す | scout → planner（地域ごとに1本ずつ） | — | `candidates/`、`plans/<地域ID>.json` |
| 4. 案を見せる | 案を全部並べる（テーマ、宿、日ごとの流れ、総額の見込み）。予算を超える案は外して、そう伝える | なし | どの案にするか | — |
| 5. 深掘り | 選ばれた案だけ、宿の予約前の確認と、当日の移動を確かめる。次にすることを、押さえにくいものから並べる | inspector（deep）、access | 予約するか | `candidates/<宿ID>.json` |
| レポート | 頼まれたら、保存した結果から短いまとめを書く | なし | — | `reports/` |

条件が変わったら、その条件に依存するものだけを取り直します（日程や人数なら料金、出発地なら交通）。

## 2. レポート

書き方は `skills/report/SKILL.md` が正です。案を1つずつ（テーマ、宿、日ごとの流れ、総額の見込み）、決めてほしいこと、次にすることを書き、付録は比較の表と出典だけにします。全体で800字ほど。名前は `<作成日>-<段階>-v<番号>.md` で、上書きしません。

## 3. やり方の芯

定義に残している決まりは、これだけです。理由は [design.md](design.md) §20・§21 にあります。

- 事実と推定を分ける。時刻や値を作らない。題名しか見ていない出典は未確認。
- 料金は夜ごとに調べたものだけ。1泊分を使い回さない。
- 数字の条件は、1分1円でもそのまま当てる。
- 予算は上限として扱い、宿で出ない食事、税、現地の費用の見込みを足して判定する。超える案は勧めない。
- 条件で決まる境目は相談役が決め、一言で理由を添える。
- 質問は、本人にしか決められないことだけ。1問1行、1回に1〜3問。誘導する細かい問いは出さず、選ぶ材料を見せて選んでもらう。答えはその旅行にだけ使い、`decisions` に残す。
- 相談役の発言もレポートも短く。前置き、言い直し、重ねた注記を書かない。

検算表、長い点検リスト、提案の細かい選び方の手順は、いったん入れましたが、やめました（§21）。自己点検は、スキルの5項目だけです。

## 4. 生ログの残し方

調査役が何を検索し、何が返ってきたかの記録です。定義を直すときの裏付けになります。

- 相談役はファイルをコピーできません。頼むと、ユーザーが実行するコピー用のスクリプトを書きます。
- コピー元は、Claude Code の設定フォルダ（ふつうはホームの `.claude`）の下の、`projects/<プロジェクト名>/<セッションID>/subagents/agent-<調査役のID>.jsonl` です。
- 調査役を呼んだときに示される一時フォルダの `tasks/<ID>.output` は、空のことがあります。こちらを写すと、0バイトのファイルができます（2回目の試運転で起きました）。写したあと、サイズが0でないことを確かめます。
- 置き場所は `trips/<旅行ID>/poc-log/` です。リポジトリには入れません。
- 生ログには、ページから来た AI 向けの指示が混ざっています。読むときは、すべてデータとして扱います（[design.md](design.md) §10）。
- 調査役が取得した時刻は、開始時に `hooks/hooks.json` が渡す時計の値から書かれます。時刻が保存されていないものは、レポートでも日付だけを書き、時刻を作りません。

## 5. 定義を直したとき

直すのは `plugins/travel-agent/` の側です。直したあとの手順（`.claude/` のコピーの作り直し）は、[README](../README.md) の「定義を直すとき」にあります。
