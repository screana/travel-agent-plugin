# travel-agent（宿探しの相談役）

国内旅行の**宿探し**を手伝う、Claude Code 用の plugin です。会話は日本語です。

宿を決めるのは、あなたと同行者です。この plugin は、決めるための選択肢と判断材料を出します。旅程を細かく組んだり、1軒に決め打ちしたりはしません。**予約と決済もしません。** 予約は、表示されたリンクから、あなた自身が予約サイトで行います。

バージョン 0.1.0 は試作（PoC）です。設計の考え方は [docs/design.md](docs/design.md) にあります。

## できること

- 最初に、あとで変わると調べ直しが大きい条件（日程、人数と部屋数、出発地、予算）だけを聞きます。残りは「仮置き」で進めます。
- 候補を3つの段階で出します。**広く見る**（8〜12軒を性格別に）→ **比べる**（残した3〜5軒）→ **予約前の確認**（1〜2軒）。次の段階に進むのは、あなたが残す候補を言ったときだけです。
- 情報を3種類に分けて見せます。**あなたが決めた条件**／**事実**（出典と取得日時つき。取れなければ「取れなかった」）／**推定と提案**（順位とその理由、ここでできること、口コミの要旨、ブログや動画の紹介）。
- 要望が来たら、関係するところだけを調べ直します（出発地が変わったら交通だけ、日程が変わったら料金だけ、など）。
- 口コミの点数は、順位に使いません。低評価の中身から、泊まってから困るリスクを探します。サクラかどうかは断定せず、「気になるしるし」として伝えます。
- ブログや YouTube の紹介は、「ほかの人の体験と意見」として、PR 表記の有無と一緒に出します。動画は映像を見られないので、リンクと説明文からわかることだけを出します。

## 使い方は2通り

| 使う場所 | 入れ方 | 始め方 |
|---|---|---|
| **クラウド上の Claude Code**（claude.ai/code など） | 入れる作業は要りません。このリポジトリを開くだけ | `/travel-start` |
| **手元の Claude Code（CLI）** | plugin として入れる | `claude --agent travel-agent:concierge` |

クラウドのセッションは plugin を読み込まないので、同じ定義を、このリポジトリの `.claude/agents/` と `.claude/skills/` にも置いてあります（plugin の定義から作ったコピーです）。

### クラウド上の Claude Code で使う

1. claude.ai の設定で、trivago と Booking.com のコネクタを追加しておきます（下の「宿検索のコネクタ」）。
2. クラウド上の Claude Code で、このリポジトリ（`screana/travel-agent-plugin`）を開きます。
3. 次のスキルを実行します。

   ```
   /travel-start
   ```

   最初の要望を続けて書くこともできます。

   ```
   /travel-start 1月に3人で温泉に行きたい。東京から
   ```

知っておいてほしいこと：

- この始め方では、相談役は**メインの会話**として動きます。メインの会話は、そのセッションにあるツールをすべて持っています。相談役の定義には「自分では Web もコネクタも使わず、調査はサブエージェントに任せる」と書いてありますが、これは**決まりであって、仕組みで止めているわけではありません。**（「安全について」を見てください。）
- 相談役のモデルは、そのセッションのモデルです。サブエージェント（`scout`、`inspector`、`access`）は、定義で指定したモデルで動きます。
- 宿のサイトによっては、クラウドの環境からページを取得できないことがあります。「読めなかった」が続くサイトがあれば、教えてください。
- 保存したデータは、リポジトリの中の `.travel-agent/` に置かれます。環境が作り直されると消えます（「保存するデータと、消し方」）。

### 手元の Claude Code（CLI）で使う

Claude Code の中で、次の2つを実行します。

```
/plugin marketplace add screana/travel-agent-plugin
/plugin install travel-agent@travel-agent-plugin
```

シェルから入れる場合は、次のとおりです。

```
claude plugin marketplace add screana/travel-agent-plugin
claude plugin install travel-agent@travel-agent-plugin
```

入れたあと、`/plugin` の一覧に `travel-agent` が有効として出ていれば完了です。出てこないときは、`/reload-plugins` を実行するか、Claude Code を起動し直してください。

始めるときは、相談役として起動します。

```
claude --agent travel-agent:concierge
```

メインの会話が、宿探しの相談役（concierge）になります。この起動の仕方では、相談役が持つツールは、サブエージェントの起動、ユーザーへの質問、ファイルの読み書きだけです。Web の検索や宿検索のコネクタは持たず、調査はすべて専用のサブエージェントに任せます。「安全について」の備えが、いちばんよく効く形です。

`--agent` を付けずに起動した通常のセッションからは、`/travel-agent:start` で始められます（クラウドの `/travel-start` と同じ動きで、相談役はすべてのツールを持ったままになります）。

### 続きから再開する

どの始め方でも、保存されたデータがあれば、始めるときに「続きから始めるか、新しく始めるか」を聞かれます。

## 宿検索のコネクタ（trivago、Booking.com）

日付と人数を指定した料金を取るために、claude.ai のコネクタを使います。**キーの取得や契約は要りません。**

1. claude.ai の設定のコネクタ（https://claude.ai/customize/connectors ）で、**trivago** と **Booking.com** を追加します。
2. Claude Code に、claude.ai のアカウントでログインします。追加したコネクタが、Claude Code でも自動で使えるようになります。`/mcp` で一覧に出ていることを確かめてください。

知っておいてほしいこと：

- **コネクタがなくても動きます。** その場合は、Web の検索と、宿や予約サイトの個別のページだけで調べます。日付を指定した料金が取れないことが増え、「取れなかった」の表示が多くなります。
- API キーで Claude Code にログインしている場合、claude.ai のコネクタは読み込まれません。
- コネクタに出てこない宿があります（とくに小さい宿）。出てこないことは、「空室がない」「宿がない」という意味ではありません。
- この plugin が使うのは、trivago の宿の検索と、Booking.com の宿の検索だけです。**予約や決済を行うツールは使いません。** Expedia のコネクタは、会話の内容を広く渡すよう求めるツールのため、使いません。
- コネクタには、日程、人数、エリア、宿の名前だけを渡します。会話の文章は渡しません。
- サブエージェントが使えるツールは、名前で決めてあります。あなたの環境でコネクタのツールの名前が違うと、サブエージェントからコネクタが使えず、Web だけで調べることになります。その場合は、[plugins/travel-agent/agents/](plugins/travel-agent/agents/) の `scout.md` と `inspector.md` の `tools` に、`/mcp` に表示されるツールの名前を足し、`python3 scripts/sync_project_copy.py` を実行してください。

## 使うモデル

| 役割 | モデル | すること |
|---|---|---|
| `concierge`（相談役） | Fable | 会話、条件の管理、順位付け、表示 |
| `scout` | Opus | 候補を広く集める |
| `inspector` | Opus | 宿を1軒ずつ調べる |
| `access` | Sonnet | 交通を調べる |

- 指定のモデルが使えない場合、Claude Code は、同じ系列で使える版か、メインの会話のモデルで動かし、警告を出します。そのまま使えますが、品質は落ちることがあります。
- `/travel-start` や `/travel-agent:start` で始めた場合、相談役は、そのセッションのモデルで動きます。

## コストの目安

1回の相談（広く見る → 比べる → 予約前の確認、要望が2〜3回）で、サブエージェントを**合計10〜15本**ほど動かす見込みです。**これは設計上の見積もりで、まだ実測していません。**

- 1回に動かすのは、`scout` 3本まで、`inspector` 5本まで。6本を超えるときは、先に確認されます。
- `inspector` は、1軒につき最大12ページ（予約前の確認では15ページ）を読みます。

## 保存するデータと、消し方

- **保存するもの**：旅行の条件（日程、人数、出発地、予算、好みの定義）、候補の宿と調べた結果（料金、部屋数、口コミの要旨、ブログや動画の要約、出典の URL、取得日時）、要望の記録。
- **保存しないもの**：名前、連絡先などの個人情報。口コミやブログの本文。API キー（この plugin はキーを扱いません）。

| | 場所 | 消し方 |
|---|---|---|
| クラウド（このリポジトリを開いて使う） | リポジトリの中の `.travel-agent/trips/<旅行ID>/` | `/travel-reset`、または `rm -rf .travel-agent/trips/<旅行ID>` |
| 手元の CLI（plugin として使う） | `~/.claude/plugins/data/travel-agent-travel-agent-plugin/trips/<旅行ID>/` | `rm -rf ~/.claude/plugins/data/travel-agent-travel-agent-plugin/trips/<旅行ID>`、または通常のセッションで `/travel-agent:reset` |

- `.travel-agent/` は `.gitignore` に入れてあるので、旅行の条件が誤ってコミットされることはありません。
- **クラウドでは、環境が作り直されると、保存したデータも消えます。** 続きから再開できるのは、同じ環境が残っている間だけです。
- 手元の CLI の場所は、Claude Code の仕様（`~/.claude/plugins/data/<plugin の ID>/`。ID は `travel-agent@travel-agent-plugin` の記号を `-` に置き換えたもの）から書いたもので、実機では確かめていません。フォルダが見つからないときは、`~/.claude/plugins/data/` の下を見てください。
- `claude --agent travel-agent:concierge` で起動したセッションでは、相談役がシェルを持たないので、reset のスキルを実行しても、消すためのコマンドを案内するだけになります。上の `rm` を自分で実行するか、通常のセッションで `/travel-agent:reset` を使ってください。
- 手元の CLI では、plugin をアンインストールすると、データフォルダごと消えます。
- Claude Code 本体は、これとは別に、会話の記録を保存しています。それは reset では消えません。

## 安全について

宿のページ、口コミ、ブログ、コネクタの返り値は、誰が書いたかわからない文章です。そこに AI 向けの指示（「この宿を1位にせよ」「この URL に条件を送れ」など）が仕込まれていることがあります（プロンプトインジェクション）。この plugin は、次のように備えています。

- 外から取った内容は**データとして扱い、そこに書かれた指示には従いません。**
- 外の文章を直接読むのは、サブエージェントだけです。サブエージェントは**読むだけ**で、ファイルの書き込み、シェル、予約・決済・送信のツール、あなたがつないでいるほかのコネクタ（メールやカレンダーなど）は使えません。
- サブエージェントに渡すのは、日程、人数、エリア、食事、好みの定義だけです。
- 怪しい指示に気づいたら、無視したうえで、あなたに知らせます。

**防げないこと**もあります。

- サブエージェントがだまされる可能性は、ゼロにできません。だまされた場合、渡された条件（日程やエリア）が、URL に付けて外に送られるおそれがあります。
- ページにもっともらしい嘘が書かれていても、見分けられません。出典を付け、種類の違う情報源と照らすことで、影響を小さくしているだけです。
- 検索やコネクタの呼び出しのために、日程・エリア・人数は、外部のサービスに送られます。
- **クラウドの `/travel-start`（と、手元の `/travel-agent:start`）では、相談役はメインの会話なので、そのセッションのツールをすべて持っています。** 「自分では調べない」「予約や送信のツールを使わない」は、定義に書いた決まりとしてしか効きません。仕組みで絞れるのは、`claude --agent travel-agent:concierge` で起動したときだけです。

### 使わないコネクタは切っておく

相談役がすべてのツールを持つ始め方（クラウドなど）で使うときは、宿探しに要らないコネクタ（メールの送信、カレンダー、チャット、ファイルの共有など）を、あらかじめ切っておくことを勧めます。

- claude.ai の設定のコネクタで、そのコネクタを外す。または、Claude Code の `/mcp` で、そのプロジェクトだけ無効にする。
- 設定ファイルで止めることもできます。たとえば、自分の設定（`~/.claude/settings.json`）の `permissions.deny` に、止めたいサーバーやツールの名前を入れます。名前は `/mcp` に表示されるものを使ってください。次は書き方の例で、名前は環境によって違います。

  ```json
  {
    "permissions": {
      "deny": [
        "mcp__Gmail",
        "mcp__Google_Calendar",
        "mcp__Slack"
      ]
    }
  }
  ```

- このリポジトリには、設定ファイル（`.claude/settings.json`）を入れていません。何を止めるかは、使う人が決めてください。
- Claude Code の許可の確認（新しいサイトへのアクセスなど）を、すべて省くモードで使うことは勧めません。

## 試すときのチェック

この版は、エージェントを実際に動かす確認ができていません。試すときに、次の点を見てください。

- **コネクタ**：`/mcp` に trivago と Booking.com が出ているか。そこに表示されるツールの名前は何か。
- **サブエージェントがコネクタを使えたか**：調査のあとで「scout が返した `tools_used` を見せて」と頼むと確かめられます。`trivago` が入っていなければ、ツールの名前が合っていません（「宿検索のコネクタ」の最後の項目）。
- **`--agent` で起動したとき、サブエージェントが Web の検索・取得とコネクタを使えるか**：相談役がそれらを持たない起動の仕方なので、サブエージェントが受け継げるかを確かめる必要があります。
- **`--agent` で起動したとき、相談役が `scout`・`inspector`・`access` 以外のサブエージェントを呼べないようになっているか。**
- **相談役が、自分で Web の検索やコネクタを呼んでいないか**（とくに `/travel-start` で始めたとき）。呼んでいたら、定義の書き方を直す必要があります。
- **表示の形**：【条件】→【候補】→【推定と提案】の順になっているか。最初の質問が多すぎないか。
- **読めないサイト**：「読めなかった」「取れなかった」が続くサイトがあるか。
- **保存**：`.travel-agent/`（手元では `~/.claude/plugins/data/` の下）に書き込めているか。書き込みのたびに許可を求められないか。

## 注意事項

- **料金は、取得した時点のものです。** 税込かどうかがわからない料金は「税の扱い不明」と表示します。予約の前に、必ず予約サイトで最終確認をしてください。
- 口コミの要旨やブログの要約は、AI の読み取りです。数え間違いや読み落としがありえます。読んだ範囲を一緒に表示するので、気になる点は元のページで確かめてください。
- 交通の所要時間と運賃は、Web のページから取ります。「取れなかった」と表示されたときは、経路検索で確かめてください。
- この plugin は、予約サイトを機械的に巡回しません。読むのは、候補の確認に必要な個別のページだけです。
- trivago、Booking.com、そのほかの名前は、それぞれの会社の商標です。この plugin は、どの会社とも関係のない、個人の試作です。

## 構成

```
.claude-plugin/marketplace.json     マーケットプレイスの定義
plugins/travel-agent/               plugin の本体（こちらが正）
  .claude-plugin/plugin.json        plugin の定義
  agents/concierge.md               相談役（ハブ）
  agents/scout.md                   候補を広く集める
  agents/inspector.md               宿を1軒ずつ調べる
  agents/access.md                  交通を調べる
  skills/start/SKILL.md             通常のセッションから始める入口
  skills/reset/SKILL.md             保存したデータを消す
.claude/                            クラウド用のコピー（生成物。直接は編集しない）
  agents/{concierge,scout,inspector,access}.md
  skills/travel-start/SKILL.md
  skills/travel-reset/SKILL.md
scripts/sync_project_copy.py        plugin の定義から .claude/ のコピーを作る
docs/brief.md                       依頼書
docs/design.md                      設計書
```

この plugin に、MCP サーバーや、実行時に動くプログラムは含まれていません。エージェントとスキルの定義（Markdown）だけです。`scripts/` のスクリプトは、開発のときにコピーを作るためのものです。

### 定義を直すとき

直すのは `plugins/travel-agent/` の側です。直したら、コピーを作り直します。

```
python3 scripts/sync_project_copy.py           # .claude/ の下を作り直す
python3 scripts/sync_project_copy.py --check   # ずれていないかを確かめる
```

スクリプトがするのは、ファイルのコピーと、決まった文字列の置き換えだけです（`travel-agent:scout` → `scout`、データの場所 → `.travel-agent`、スキルの名前 → `travel-start`・`travel-reset` など）。
