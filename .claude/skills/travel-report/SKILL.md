作った旅行の案を、同行者に見せる**短いまとめ**にします。読み手は、会話に参加していない同行者です。知りたいのは、どんな旅行になるか、いくらか、次に何をするかだけです。

対象の旅行：$ARGUMENTS（空なら、いま相談している旅行）
データフォルダ：`.travel-agent`

## 手順

1. `trips/<旅行ID>/` の `conditions.json`、`plans/`、`candidates/`、`access.json` を読みます。材料はこれだけです。新しく調べず、記憶で値を足しません。
2. 取得から24時間以上たった料金があれば、取り直すかを先に聞きます。
3. 下の形で書き、自己点検をしてから、`reports/<作成日>-<段階>-v<番号>.md` に保存します（段階は `wide`＝行き先の一覧、`compare`＝案、`final`＝選んだ案。上書きしない）。全文を会話にも出します。

## 形

本文は**全体で800字ほど**。前置き、読み方の説明、重ねた注記は書きません。細かい事実は保存データにあるので、載せません。

```markdown
# 旅行の案：〔時期と日数〕（〔作成日〕時点）

## 案A　〔地域〕：〔テーマを1行〕
- 宿：〔宿の名前（夜ごとの食事）〕
- 1日目：〔流れを1〜2行〕
- 2日目：〔流れを1〜2行〕
- 総額の見込み：1人 〔額〕（推定。宿、交通、食事、税、現地の費用）
- 気をつけること：〔選ぶ前に知っておくべきことだけ。なければ書かない〕

〔案の数だけ。数を絞らない。選んだあとのまとめ（`final`）なら、その1案だけ〕

## 決めてほしいこと
〔1行。例：どの案にしますか？〕

## 次にすること
- 〔押さえにくいものから順に。いつまでに、だれが、何を。数行〕

---
## 付録
| | 案A | 案B |
|---|---|---|
| 総額の見込み（出発地ごと） | | |
| 予算までの余り | | |
| 所要時間（出発地ごと） | | |
| 宿で出る食事 | | |

出典：〔案ごとに、予約サイト名とリンク、取得した日〕
料金は取得した時点のものです。予約と最終確認は、各予約サイトで行ってください。AI が作った資料です。
```

## 決まり

- **事実と推定を分ける。** 確かめきれていないことにだけ「（未確認）」「（推定）」「（未調査）」を付けます。時刻、値、店や場所の名前を作りません。
- **料金は、夜ごとにその日付で調べたものだけ。** 1泊分を使い回しません。欠けた夜があれば、総額は出しません。
- **予算は上限として扱う**（`budget.firmness` が別の値なら、それに従う）。総額は、宿で出ない食事、税、現地の費用の見込みを足した額です。超える案は載せず、外したことを1行で書きます。
- **条件で決まる境目は自分で決め、一言で理由を添える。** 問いは、本人にしか決められないことだけにします。
- 「あきらめること」を並べません。口コミの点数で優劣を言いません。会話や plugin の中だけの言葉、強める言葉、絵文字、個人的な情報は書きません。

## 自己点検

1. 案ごとに、どんな旅行で、いくらかが、数行でわかるか。
2. 数字は保存データと合っているか。作った値、使い回した料金はないか。
3. 予算を超える案を載せていないか。
4. 未確認、推定、未調査に印があるか。
5. 800字ほどに収まり、同じことを2度書いていないか。
